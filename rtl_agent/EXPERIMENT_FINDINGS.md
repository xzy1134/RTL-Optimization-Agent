# RTL 优化 Agent 的核心问题与实验证据

当前最需要验证的是：给定同一个失败候选和有限的剩余 API 预算，路径、反例或单元面积反馈能否提高下一轮产生有效面积改善的概率。有效改善要求组合形式等价验证 PASS、逻辑深度满足原约束，并且在相同综合配置下映射面积严格下降。

## 三轮对照

两个电路分别使用 deepseek-flash 运行旧、新反馈各一次。每组实际调用 3 次，深度上限分别为 barrel 4、addsubz 10。同一电路两组的综合配置指纹一致。

| 电路与反馈 | 生成 RTL / 调用 | 形式 PASS / 生成 RTL | 接受 / 调用 | 基线 → 最佳面积 | 实际 Token |
|---|---:|---:|---:|---:|---:|
| barrel 旧 | 1/3 | 0/1 | 0/3 | 39.368 → 39.368 | 12,409 |
| barrel 新 | 3/3 | 3/3 | 0/3 | 39.368 → 39.368 | 15,716 |
| addsubz 旧 | 2/3 | 2/2 | 0/3 | 75.544 → 75.544 | 8,916 |
| addsubz 新 | 2/3 | 2/2 | 1/3 | 75.544 → 75.278 | 9,586 |

barrel 新版三份候选的源码哈希各不相同，但三次测量都得到面积 39.368、深度 4。第一轮的标准单元类型和数量与父版相同，其中 15 个 MUX2_X1 合计面积 27.930。这说明按源码哈希去重仍会放行综合收益相同的尝试。仅凭面积、深度和直方图无法判定网表连线完全相同。

addsubz 旧版的两个候选都通过形式验证且减小了面积，但深度均为 11，超出上限 10。新版首轮同样测得面积 73.682、深度 11，第二轮响应格式不合格，第三轮得到面积 75.278、深度 10，合法改善 0.35%。一次格式错误用掉了三次调用中的一次。两组实际 Token 总量分别为旧版 21,325、新版 25,302；新版多用约 18.6%。这些数字描述本次实验，不能当作平均收益或平均成本。

## 历史最佳与可复现性

addsubz 的另一次五轮实验从同一基线出发。第一轮面积 73.682、深度 11，被拒绝。第二轮共享加减法结构达到 61.978 / 8，第四轮在第二轮版本上改进进位表达式，达到 56.392 / 10，面积降低 25.35%。第五轮形式验证失败，第四轮最佳设计仍被保留。即使只看前三次调用，这次实验也已取得约 17.96% 的合法改善。因此，五轮与三轮的预算差异无法单独解释结果差距。

这份记录证明搜索闭环能够保留并继续改进已验证的候选。新旧对照各只有一次独立运行，首轮候选的源码哈希也不同。目前无法估计 25.35% 的复现概率，或把收益差距归因于模型采样、提示词或诊断中的某一个因素。跨实验继续优化历史最佳，与评估新诊断的独立效果，是两个不同的实验目标。

## 可检验的下一步

保存同一份深度超限 RTL 和同一份父版本，复制相同历史、策略、剩余调用数和 Token 上限。每对实验只改变输入模型的诊断摘要，并在多个电路上重复。主要指标采用“下一次调用获得合法面积改善的次数 / 全部下一次调用”，同时记录面积变化、格式错误、实测面积与深度均无变化的次数及 Token。这样可以直接衡量一条诊断能否帮助模型作出更有效的下一次改写。

## 固定失败现场后的五对真实调用

选用 addsubz 新版三轮实验的首轮失败 RTL（面积 73.682、深度 11，黄金设计面积 75.544、深度上限 10）。复制相同 RTL、策略、一次失败历史和任务目标。B 单独增加该候选实测的 b[0] 到 result_is_zero[0] 的 11 层路径和检查建议。发送前核对移除该段后两组任务数据相等，系统消息相同。各轮独立，顺序 AB、BA、AB、BA、AB。模型 deepseek-flash，输出上限 2048，每次机会最多一次请求。

| 对次 | A 结果（面积 / 深度） | A Token | B 结果（面积 / 深度） | B Token |
|---|---|---:|---|---:|
| 1 | 接受 61.978 / 8 | 3831 | NO_CHANGE | 3156 |
| 2 | 接受 56.392 / 10 | 3345 | 形式 FAIL | 3383 |
| 3 | 面积未改善 75.810 / 10 | 3168 | 深度超限 73.682 / 11 | 3398 |
| 4 | 接受 56.392 / 10 | 3787 | 形式 FAIL | 3467 |
| 5 | 面积未改善 75.810 / 10 | 3196 | 接受 75.278 / 10 | 3309 |

A 成功 3/5，B 成功 1/5；保住失败候选全部面积收益的次数分别为 3/5、0/5。仅 A 成功 3 对，仅 B 成功 1 对，两边均未成功 1 对。A 消耗 17327 Token，B 消耗 16713 Token。每次均重新验证、综合，同一测量结果可在独立调用中重复出现。实验支持在此固定起点上通过基础反馈再次得到 56.392 / 10；五对观测不足以断定路径提示普遍有害，也不能单独归因于路径数据或随附建议。

## A/B1/B2 消融收尾与 B3 离线草案

同一起点 73.682 / 11，合法基线 75.544 / 10。每组 3 次独立调用，按实际发送消息和服务端 usage 复核。九次均请求关闭 thinking，九份 usage 均未单列思考 Token，计为“未报告”。总耗时列为每次从发起到本地验证评分结束的实测秒数。

九次累计输入 17,715、输出 2,465、总计 20,180 Token。API 耗时之和 22.950 秒，逐次端到端耗时之和 23.988 秒。A 的两个形式失败分别涉及错误的跨段进位和操作数拼接；成功的 2-A 将减法加一项移到 a 一侧，得到 72.618 / 10，优于基线 3.87%。B1 有两个 NO_CHANGE、一个深度超限；B2 有一个 NO_CHANGE、一个格式错误、一个深度超限。合法改善和严格改善均为 A 1/3、B1 0/3、B2 0/3。五份返回的完整候选源码内容各异。

对已有 mapped.json 从命名顶层输出按位回溯，对每个标准单元记录单元类型、参数、具名输入/输出引脚、位索引、输入端口或驱动实例，保留多扇出引用。按首次访问次序替换实例名，核对遍历覆盖全部单元，再比较规范化结构。1-B1、2-B2 和起点均含 56 个单元，类型数量及完整引脚连接一致。2-A 也含 56 个单元，但类型分布和连接结构不同。三份有映射结果的候选中，按首次出现计有一次候选间重复；相对起点，有两次结构重复。

实际发送的系统消息及基础任务数据三组相同。B1 每次比 A 多 584 个输入 Token（2,156 vs 1,572），唯一增量是 feedback[0].path。其中包含深度 11、起止端口和 11 条逐门连接记录。每条重复字段名 cell、type、input_pin、output_pin、src、dst，以及 ABC 自动实例名的共同前缀；相邻连接共享中间位 ID。深度也已经出现在 parent_depth。584 是服务端报告的整体增量，未取得逐字段分词统计。B2 比 B1 又多 21 个输入 Token，新增一句检查该路径并缩短串行依赖的建议。

观察到 B1、B2 各自唯一通过形式验证的 RTL 都保留算术通路，改用归约形式做零检测，最终映射回起点。详细路径可能诱导模型把端点当成修改目标，这是待验证假设。每组只生成三次，无法从本组数据判定原因。

B3 直接复制实际 A 消息，仅在用户 JSON 末尾新增 path_context，包含起点 b[0]、终点 result_is_zero[0]、层数 11 及全局改写许可。系统消息、两份 RTL、面积目标、等价与接口约束、策略自由度和预算完整保留。离线反向删除新增字段已核对与 A 相等。B3 同时缩短证据并提示全局自由度，未来比较只能评价二者的组合效果。本次未发送 B3，实际 Token 和优化效果待测。
