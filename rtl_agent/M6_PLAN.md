# 默认反馈与后续开发范围

最新决定已恢复历史成功实验 deepseek-search-ouw3ksjt 的完整反馈构建。默认含策略提示、结构证据、实际改动和最佳版本摘要，关闭 M5 自动诊断。每三轮回到基线的父版本规则继续使用。基础 A 仅保留供显式实验调用。下文记录此前基础 A 默认方案，已由上述决定替代。

默认模式采用 addsubz A-messages.json 的结构和系统规则。保留完整原始及当前父版源码、面积和深度、约束、简短等价及失败状态、本轮优化目标。策略列表为空，主要方向为 open_exploration。完整请求及历史仍在本地，详细策略证据、最佳版本摘要、逐门路径、局部建议不自动进入基础消息。当前默认发送内容不包含完整跨轮修改 diff。使用相同的实验任务数据可逐字复现归档 A；正常运行时电路、父版、指标、剩余预算和反馈状态按实际值更新。

CLI 默认关闭 M5，--diagnostics 显式启用。Python run_search(..., diagnostics=True) 同样支持。--legacy-feedback 是基础模式的兼容参数。系统 Prompt 文件保持原文。原消融脚本显式使用原来的完整渲染模式，保留既有实验分组定义。

原串行图依次执行初始化、基线、预算控制、父版/策略分析、生成、语法与接口检查及源码哈希去重、与最初原始 RTL 的形式证明、综合、接受判定、历史保存和停止检查。默认第 1、2 轮从合法最佳出发（尚无改善时即基线），第 3 轮回基线，随后每三轮重复。M2 按当前父版重新分析，内部按最少尝试次数、优先级和 ID 排序，但默认消息不限定模型采用内部首选策略。

候选形式 FAIL/UNKNOWN/ERROR 不进入综合评分。形式 PASS 才综合。只有完整可比配置、深度合格且严格小于合法最佳面积才能晋升。深度超限或面积无改善均记录后继续；失败候选不成为父版。默认不执行 M5 的连续位置失败切换。显式诊断实验模式仍保留其既有的连续两次同位置失败时调整父版和策略顺序的规则。

现有接口可支持后续设计：select_node 选择父版与建议方向，generate_node 构建 ModelRequest，record_node 写入 history/recent_trials、更新 best 和 no_improvement_rounds，control_node 检查候选数、轮数、连续无改善、API 次数、Token 和时间预算。best、baseline、parent、strategy_attempts、attempted_hashes 和 recent_trials 已在 State 中。后续 Explore/Exploit 设计可以复用这些接口。本轮仅恢复基础默认模式，不新增控制器决策或映射结构去重节点。离线网表比较与实验工件继续保留。

验证采用归档 A 的消息逐字比对、Mock 默认关闭诊断并保留每三轮回基线的检查、显式诊断回归、完整原有测试。测试期间不调用付费 API。归档 A 在 work 中，外部干净检出缺少归档时，仅该逐字回放测试会标记跳过，其余测试仍可执行。
